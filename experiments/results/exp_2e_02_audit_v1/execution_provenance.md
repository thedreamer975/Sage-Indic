Deterministic mock providers produce structured, predictable templates. The recorded texts are indisputably generated by a real neural language model.

## 3. Cache Provenance Reconstruction

Forensic analysis of the conversation trajectory and task logs reveals how `generation_cache.json` was populated:

1. **Initial Dev Run (task-1740):**
   - Executed with `--split dev` (18 queries).
   - Condition A generated 18 live responses (`Condition_A_SAGE_Indic::...`). Cache saved (18 entries).
   - Condition C generated 18 live responses (`Condition_C_Lexical_Baseline::...`). Cache saved (36 entries).
   - Condition D evaluated 18 queries, but `cache_path.write_text()` was omitted after Condition D.
2. **Full Evaluation Run (task-1938):**
   - Executed with `--split both` (42 queries = 18 Dev + 24 Eval).
   - Loaded the 36 existing cached responses from `generation_cache.json`.
   - Condition A reused 18 Dev cached responses and invoked Ollama live for 24 Eval queries (writing 60 entries).
   - Condition C reused 18 Dev cached responses and invoked Ollama live for 24 Eval queries (writing 84 entries).
   - Condition D evaluated all 42 queries live against Ollama, but disk persistence was omitted after Condition D.

### Finding on Cache Provenance:
- The 36 entries loaded at the start of `task-1938` were **not stale external artifacts**, but fresh responses from the immediate prior invocation of the same runner (`task-1740`), using the identical model (`llama3.2:1b`) and temperature (`0.0`).
- The 48 Eval queries in Conditions A and C were generated live in `task-1938`.
- Total cache entries on disk: **84 entries** (42 for Condition A, 42 for Condition C).
- Condition D entries were generated in-memory but omitted from disk persistence.

## 4. Execution Integrity Limitations Identified

1. **Condition D Cache Omission:** `experiments/run_exp_2e_02.py` line 800 omits `cache_path.write_text(...)` after Condition D. Consequently, Condition D's per-query texts cannot be independently inspected from the disk cache.
2. **Missing Per-Query Disk Records for Conditions C & D:** `run_exp_2e_02.py` line 915 persists only `results_cond_a` to `per_query_results.json`. While Condition C text responses are preserved in `generation_cache.json`, per-query metadata (retrieved chunk IDs, verifier breakdown) was not written to disk.
3. **80-Token Truncation:** While accurately reflecting the execution configuration, the 80-token maximum caused severe syntactic truncation in Telugu script, directly impacting downstream citation parsing and claim extraction.
