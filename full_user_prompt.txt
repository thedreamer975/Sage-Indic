# SAGE-Indic — EXP-2E-02: Reproducible End-to-End Grounded Factuality Evaluation

## Mission

Execute the first controlled end-to-end evaluation of SAGE-Indic, connecting the existing retrieval, generation, claim-extraction, verification, provenance, and answer-eligibility components.

The research objective is to measure whether SAGE-Indic can answer factual questions in:
1. Native Telugu (`te`)
2. Romanized Telugu (`te-Latn`)
3. Telugu-English code-mixed text (`te-en`)

using retrieved evidence while reducing unsupported factual assertions.

This is a research experiment, not a demo. The objective is to produce reproducible measurements, inspectable predictions, error analyses, and appropriately qualified findings that may support a research paper.

Do not ask for approval between implementation steps. Complete all feasible work within the existing repository. If a required model, credential, dependency, or dataset is unavailable, document the blocker precisely and continue with the portions that can be evaluated honestly.

Do not fabricate results, reference answers, annotations, model responses, provider execution, citations, or statistical significance.

Use the same eligible queries, generator model, prompt policy, and evaluation definitions wherever possible.

- Frozen chosen retrieval configuration.
- Evidence-grounded generation.
- Current claim extraction.
- `RelationAwareClaimVerifier`.
- Existing answer-eligibility policy.

**Condition B — Original verification baseline**
- Same generated drafts and evidence as Condition A.
- Substitute the frozen `LinguisticClaimVerifier` for the relation-aware verifier.
- Measure the effect of verification strategy without changing generation.

**Condition C — Retrieval comparison**
- Same queries and generator configuration.
- Compare a justified lexical baseline with the chosen normalized or cross-script retrieval configuration.
- Keep evidence limits and prompt templates fixed.

**Condition D — Retrieval/evidence ablation**
- If safe and meaningful, evaluate generation with no retrieved evidence or a controlled evidence ablation on a separate research condition.
- Clearly label this as an ablation, not as a valid grounded-answer system.
- Never expose unsupported outputs as verified answers.

Do not force all four conditions if the current interfaces cannot support a valid comparison. Implement the feasible conditions and document the rest as blocked.

The most important paired comparison is Condition A versus Condition B using identical drafts and evidence. This isolates the effect of the verifier more cleanly than comparing independently generated answers.

If generation itself is compared across retrieval conditions, use the same model version, prompt template, generation settings, and evidence budget.

## 6. Define and calculate metrics carefully

Implement or verify the evaluation code before interpreting results.

### A. End-to-end answer quality

Where independent reference answers or fact annotations exist, report:
- Answer-level correctness.
- Essential-fact coverage/completeness.
- Unsupported factual assertion rate.
- Contradiction rate.
- Abstention rate.
- Correct abstention rate on unanswerable queries.
- Incorrect abstention rate on answerable queries.

Define each metric explicitly, including its denominator and treatment of failures.

Do not use lexical similarity to a reference answer as the sole measure of factual correctness.

### B. Claim-level factuality

Against independently labeled claims, report:
- Supported-claim precision and recall.
- Contradicted-claim precision and recall.
- Unsupported/insufficient-evidence outcomes.
- False `SUPPORTED` count and rate.
- Claim-level confusion matrix and macro-F1 where appropriate.
- Results for compound or partially supported claims when sufficient examples exist.

Distinguish the verifier's predicted outcome from the independent gold label.

### C. Citation and provenance

Report:
- Citation identifier validity.
- Citation coverage for factual claims.
- Evidence entailment/support rate, only where claims and citations have been independently judged.
- Missing citations.
- Invalid or invented citations.
- Citations pointing to valid but irrelevant passages.

A valid source ID is not proof of entailment.

### D. Retrieval

Report:
- Recall@1 and Recall@5.
- MRR@10 and nDCG@10 where the qrels support those metrics.
- Answerable-query coverage.
- Retrieval behavior on unanswerable queries.
- Results by native Telugu, Romanized Telugu, and code-mixed modality.

Clearly distinguish retrieval relevance from factual support.

### E. Operational behavior

Report:
- Successful end-to-end completions.
- Provider failure and timeout counts.
- Mean and median latency.
- Token usage and cost, only when reliably available.
- Results per query and aggregated results.

Break down results by modality and answerability where sample sizes allow. Always show the underlying counts next to percentages.

Do not report undefined metrics as zero. Explain when a metric cannot be computed.
